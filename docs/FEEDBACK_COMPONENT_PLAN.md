# User Feedback Component - Implementation Plan

## Overview
Add a user feedback component that appears on every page, allowing users to submit bugs, design suggestions, feature requests, and general feedback.

---

## 1. Component Design & UI/UX

### 1.1 Button Placement
- **Location**: Top right corner, alongside Donate and Auth buttons
- **Position**: Between Donate button and Auth buttons (or after Auth buttons if space is tight)
- **Style**: Small, unobtrusive button that matches existing design language
- **Icon**: Chat bubble icon or feedback icon (from Heroicons)
- **Text**: "Feedback" (visible on both desktop and mobile for clarity)

### 1.2 Modal/Form Design
When clicked, opens a modal with:
- **Title**: "Send Feedback"
- **Feedback Type** (optional dropdown):
  - Bug Report
  - Feature Request
  - Design Suggestion
  - General Feedback
- **Text Input**: 
  - Multi-line textarea
  - Character limit: **1000 characters** (with counter showing "X/1000")
  - Placeholder: "Tell us what's on your mind..."
- **Email Field** (optional):
  - Pre-filled if user is logged in
  - Optional for anonymous users
  - Label: "Email (optional - for follow-up)"
- **Submit Button**: "Send Feedback"
- **Close Button**: X icon in top-right corner

### 1.3 Success State
After submission:
- Show success message: "Thank you! Your feedback has been received."
- Show "Close" button for manual dismissal (no auto-close)
- Optional: Show a subtle toast notification

### 1.4 Error Handling
- Show inline error messages for:
  - Empty feedback text
  - Feedback exceeding character limit
  - Network errors
  - Invalid email format (if provided)

## 2. Data Storage Strategy

### 2.1 Database Table: `user_feedback`

**Recommended Approach**: Store in database + send email notification

**Table Schema**:
```sql
CREATE TABLE user_feedback (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  
  -- User Information (optional - anonymous users can submit)
  user_id UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  user_email TEXT, -- Optional email from form (even if not logged in)
  
  -- Feedback Content
  feedback_type TEXT, -- 'bug', 'feature', 'design', 'general', NULL
  message TEXT NOT NULL, -- The actual feedback text (max 1000 chars)
  
  -- Metadata
  user_agent TEXT, -- Browser/device info for bug reports
  page_url TEXT, -- URL where feedback was submitted
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL,
  
  -- Admin Fields (for future use)
  status TEXT DEFAULT 'new', -- 'new', 'reviewed', 'resolved', 'archived'
  admin_notes TEXT,
  resolved_at TIMESTAMPTZ
);

-- Indexes
CREATE INDEX idx_user_feedback_created_at ON user_feedback(created_at DESC);
CREATE INDEX idx_user_feedback_status ON user_feedback(status);
CREATE INDEX idx_user_feedback_user_id ON user_feedback(user_id);
```

**Why Database + Email?**
- ✅ **Database**: Enables tracking, analytics, search, and future admin dashboard
- ✅ **Email**: Immediate notification to support team
- ✅ **Best of both worlds**: Searchable history + real-time alerts

### 2.2 Alternative Approaches Considered

**Option A: Email Only**
- ❌ No searchability
- ❌ No analytics
- ❌ Harder to track resolution
- ✅ Simple implementation

**Option B: Database Only**
- ❌ No immediate notification
- ❌ Requires checking database manually
- ✅ Better for long-term tracking

**Option C: Database + Email (RECOMMENDED)** ✅
- ✅ Searchable, trackable, analyzable
- ✅ Immediate email notification
- ✅ Future-proof for admin dashboard

## 3. Backend API Design

### 3.1 Endpoint: `POST /api/feedback`

**Request Body**:
```json
{
  "message": "The playlist creation is taking too long...",
  "feedbackType": "bug", // optional: 'bug' | 'feature' | 'design' | 'general'
  "email": "user@example.com" // optional
}
```

**Response** (Success):
```json
{
  "success": true,
  "feedbackId": 123
}
```

**Response** (Error):
```json
{
  "success": false,
  "error": "Message is required and must be 1000 characters or less."
}
```

**Implementation Details**:
1. Validate message (required, max 1000 chars)
2. Validate email format if provided
3. Extract user info from auth token (if logged in)
4. Get user agent and page URL from request headers
5. Insert into `user_feedback` table
6. Send email notification to support (`livemusiccurator@gmail.com`)
7. Return success response

### 3.2 Email Notification

**Email Service**: Use existing Resend service (`server/utils/emailService.js`)

**Email Template**:
- **To**: `livemusiccurator@gmail.com` (or `SUPPORT_EMAIL` env var)
- **Subject**: `[Feedback] Bug Report - Live Music Curator` (or appropriate type)
- **Body**: 
  ```
  New feedback received:
  
  Type: Bug Report
  From: user@example.com (or "Anonymous")
  User ID: abc-123 (or "Not logged in")
  
  Message:
  [User's feedback message here]
  
  Context:
  Page: https://livemusiccurator.com/
  Browser: Chrome 120.0
  Timestamp: 2025-01-15 10:30:00 UTC
  
  View in database: [Link to admin dashboard if available]
  ```
